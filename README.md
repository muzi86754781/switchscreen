# SwitchScreen — 跨平台软件 KVM

两台电脑（Mac / Windows 任意组合）共用**一个显示器 + 一套物理键鼠**，提供 3 大功能：

1. **切换电脑**：自定义快捷键，一键把显示器 + 键鼠控制权切到另一台。
2. **剪贴板同步**：在任意一台复制，另一台可直接粘贴（可开关）。
3. **共用键鼠**：主机捕获物理键鼠输入并转发到对端注入；可随时选择「共用」或「各自用各自的」。

---

## 工作原理（单显示器模型）

```
        ┌──────────────┐        DDC/CI        ┌─────────────────┐
   PC-A │ 主机(接键鼠) │ ─── 切输入源 ───────▶ │                 │
   (Win)│ uiohook 捕获 │ ─── WS 转发键鼠 ───▶  │   显示器 HDMI1  │
        │ robotjs注入  │ ◀── WS 回传剪贴板 ──  │                 │
        └──────────────┘                      │   HDMI2 ← PC-B  │
        ┌──────────────┐                      └─────────────────┘
   PC-B │ 客户端       │
   (Mac)│ robotjs注入  │
        └──────────────┘
```

- **主机（host）**：接了物理键鼠的那台，负责 `uiohook-napi`（libuiohook 的 N-API 封装）捕获输入。
- **客户端（client）**：接收转发来的输入并用 `robotjs` 注入。
- **切换**：快捷键触发 → 用 DDC/CI 把显示器切到目标机的输入口 → 主机转发目标改为该机。
- **共用键鼠开关关掉时**：主机不再捕获/转发，各自用各自本机的键鼠（此时显示哪台由显示器决定）。

> 想看「鼠标滑过屏幕边缘就接管另一台」的 Synergy 模型？选「共用键鼠」即可，
> 软件已按屏幕边界做无缝转发（见下文「共用键鼠：无缝移动」），传输层不变。

## 操作界面（GUI）

启动后是一个常驻托盘的主窗口，三个标签页：

| 标签 | 内容 |
|------|------|
| **窗口顶部** | 常驻提示区：第一行连接状态（已连接几台设备 / 未连接等待发现），第二行说明文字，第三行**当前键鼠模式**；右侧列出在线设备名，**只在 Mac 缺少辅助功能权限时**才出现「辅助功能未授权 · 去授权」按钮。局域网自动发现，不需要配对码 |
| **切换电脑** | **设备与显示器**：一台设备一行，**每行两列** —— 左列是电脑信息（图标、可点击改名的名字、状态、接了几块屏、「全部切到这台」），右列是这台电脑与各块屏的**排列图**：按系统设置里的**真实坐标**摆开（左右、上下、相对大小、笔记本内建屏都在图上），`显示器 A` 就是系统里最左边那块。**电脑和显示器分别着色**（电脑 1 + 它点亮的屏是同一种颜色，电脑 2 + 它点亮的屏是另一种颜色，没被点亮的灰着），不再整行高亮。点「全部切到这台」= 所有屏都切过去；**点某一块屏 = 只把那一块切过去**；点接口标签可就地改口；快捷操作（全局切换键 + **显示器 A/B/C 各自的快捷键**、登录时启动）；底部实时状态。**不再有独立的「接口映射」区域和底部一键切换大按钮** |
| **传输与剪贴板** | **左右两栏**：左栏发送（剪贴板同步开关、发送到多选、拖拽文件 / 选择文件、发送文字、超过 1GB 询问、免确认自动接收开关），右栏上方是**接收目录**、下方是**传输记录**（进度 / 取消 / 在文件夹中显示；**文本记录点开可看全文并一键拷贝**；**文件记录点一下就在文件夹里选中**；右侧 × 删除单条，可一键清空已结束的记录） |
| **共用键鼠** | **键鼠模式**（各用各的 / 共用本机键鼠 / 共用对端键鼠）、无缝移动开关、**按键兼容**（⌘ ⇄ Ctrl 三档映射 + 按键诊断）。「设备排列」区域已移除，边缘穿越不再依赖手动排序 |

实现位置：`electron/main.js`（窗口 + 托盘 + IPC）、`electron/preload.js`（安全桥）、`electron/services.js`（状态聚合与系统能力）、`electron/renderer/`（HTML/CSS/JS 界面）。

界面上的开关都是**即时生效**的：配置写回 `~/.switchscreen/config.json`，`peer` 持有同一配置引用，不需要重启。

## 安装（每台机器都要装）

```bash
npm install        # uiohook-napi 自带 N-API 预编译；只有 robotjs 需要本地编译
```

- Windows：需安装 [Windows Build Tools](https://github.com/Microsoft/nodejs-guidance)（`npm install --global windows-build-tools` 或 Visual Studio 生成工具 + Python）。
- macOS：需 Xcode Command Line Tools；首次运行要在「系统设置 → 隐私与安全性 → 辅助功能 / 输入监控」里授权终端/Node。
- Linux：需 `libudev`、`libx11`、`libxtst` 等开发包；DDC 用 `ddcutil`。

> 注意：键鼠捕获用 `uiohook-napi`，它是 **N-API** 并且 npm 包里就带着各平台预编译的 `.node`，
> 换 Electron 版本、换机器都不用重编；只有注入用的 `robotjs` 需要在目标机器上编译。

## 配置

配置文件位于 `~/.switchscreen/config.json`（`src/config.js` 负责读写，首次运行生成默认值）。

关键字段：

| 字段 | 说明 |
|------|------|
| `peerName` | 本机网络标识（用于发现和去重，一般不用改） |
| `port` | WebSocket 控制端口 |
| `shareInput` | 共用键鼠总开关（false=各自用各自的） |
| `clipboardSync` | 剪贴板同步开关 |
| `switchHotkey` | 命令行模式的切换快捷键，`{keycode, ctrl, alt, shift, meta}` |
| `isHost` | 本机是否接了物理键鼠（捕获端） |
| `monitor.command` | 按平台填写的 DDC 切换命令模板（GUI 走内置 DDC，这里只是兜底） |
| `peers[<名字>].input` | 旧字段：该对端对应的输入源值；新版本按屏配置见 `ui.portMap` |
| `ui.displayName` | **本机显示名**，界面里点电脑名字即可改，会通过 `meta` 同步给其它设备 |
| `ui.portMap` | 每块屏 × 每台电脑的接口：`{ "ddc:0": { "PC-A": "0x11", "PC-B": "0x12" } }`，键是设备身份（`peerName`），空字符串=这块屏不给这台电脑切 |
| `ui.hotkeys.global` | 全局切换键（在在线设备间轮换），默认 `F12` |
| `ui.hotkeys.monitor` | 每块屏的专属切换键：`{ "ddc:0": "CommandOrControl+Alt+1" }` |
| `ui.edgeSwitch` | 鼠标推到屏幕边缘自动切换（默认 `true`） |
| `ui.modMap` | 修饰键映射：`cmd-ctrl`（默认）/ `swap` / `off` |
| `ui.keyDebug` | 按键诊断：状态栏打印原始键码（默认 `false`） |
| `ui.autoAccept` | 是否免确认自动接收文件（默认 `false`，即每次弹「接收 / 取消」） |
| `ui.targetPeers` | 上次选中的发送对象（数组，支持多选；不在线时自动回退到第一台） |

> 局域网内靠 UDP 广播自动发现，**没有配对码/连接密码**这一步；两台在同一个网段、都打开软件即可互连。

设置快捷键（交互录制）：

```bash
npm run record-hotkey
```

## 运行

两台机器都执行：

```bash
npm start
```

启动后会：
1. UDP 广播发现局域网内的另一台；
2. 自动建立 WebSocket 链路（按名字字典序只建一条，避免双向重复）；
3. 开始剪贴板轮询同步；
4. 监听切换快捷键；主机在 `shareInput` 开启时捕获并转发键鼠。

## macOS 兼容性

- **构建目标**：`minimumSystemVersion = 11.0`（Big Sur）及以上；**macOS 13 Ventura（含 13.7.8）已覆盖**。
- **双架构**：CI 分别产出 `switchscreen-mac-x64`（Intel）与 `switchscreen-mac-arm64`（Apple Silicon）。
  在 Mac 上 `uname -m` 看是 `x86_64` 还是 `arm64`，下载对应包即可（下载错架构会提示「应用已损坏/无法打开」）。
- **权限**：首次使用「共用键鼠」需在「系统设置 → 隐私与安全性 → 辅助功能」里勾选 SwitchScreen，
  否则 `robotjs` 无法注入、`iohook` 无法捕获；界面「共用键鼠」页有「打开辅助功能设置」按钮直达。
- **DDC 切换**：**无需你安装任何工具**。Windows 直接调用系统自带 `dxva2.dll`；macOS 安装包里已内置
  `m1ddc`（Apple Silicon）或 `ddcctl`（Intel）。详见下一节。
- **睡眠唤醒**：合盖/休眠后 WebSocket 会断开，唤醒后由 UDP 广播自动重新配对（数秒内）。

## 显示切换（DDC/CI）怎么工作

| 平台 | 实现方式 | 依赖 |
|------|----------|------|
| Windows | 内置 PowerShell + 内嵌 C# P/Invoke 调用 `dxva2.dll`（`EnumDisplayMonitors` → `GetPhysicalMonitorsFromHMONITOR` → `SetVCPFeature(0x60, value)`） | 无（系统自带） |
| macOS Apple Silicon | 随包内置 `m1ddc`（CI 从源码编译，放在 `Resources/tools/`） | 无 |
| macOS Intel | 随包内置 `ddcctl`（CI 交叉编译 x86_64） | 无 |

- 兜底顺序：内置实现 → 随包工具 → PATH 里的 `m1ddc`/`ddcctl`/`ddcutil`/`ControlMyMonitor`。
- **重要**：DDC 指令只能由「显示器当前正在显示的那台机器」发出。所以切换回本机时，
  软件会通过 WebSocket 把 `ddc` 请求转给对端，让对端去切 —— 这样两个方向都能切。
- 若显示器 OSD 里关闭了 DDC/CI，写入会被拒绝（Windows 返回错误码 31），界面会明确提示
  「显示器拒绝了 DDC 指令（请在显示器菜单里开启 DDC/CI）」。
- 界面「连接与目标」卡片会**直接列出所有检测到的显示器**（不使用下拉框）。每台显示器下面分两行
  「本机 / 对端」，用**接口芯片按钮**（HDMI1 / HDMI2 / DP1 / DP2 / USB-C…）点选这台显示器分别接在哪台电脑的哪个口。
  这样多显示器各接不同端口时也能精确切换（例如显示器 1 接 Windows 的 HDMI1 / Mac 的 HDMI2，
  显示器 2 只接 Windows —— 后者在对端那一行留空即可，切换时不会被错误切走）。
  - 未逐台配置时，回退到一组全局接口值，行为与以前一致（所有显示器一起切到同一个口）。
  - 当前输入源所在的芯片会带一个 `•` 标记。
- 点「切换」或按快捷键时，**所有已配置的显示器会在一次 DDC 批量里一起切**（Windows 单个 PowerShell 进程 / macOS 顺序下发），
  并在界面上显示 `已切换 / 2-2 台显示器 / 失败原因`。
- 界面「连接与目标」下方会显示 `当前输入：HDMI1 · DDC 可用`，可据此判断链路是否正常。

## 共用键鼠：无缝移动

选择「共用本机键鼠」（或「共用对端键鼠」）后，只要把鼠标推到屏幕的某一边，画面与键鼠控制权
就一起过去；在对端把鼠标推回来，又立刻回到本机。整个过程不需要按快捷键。

| 配置 | 说明 |
|------|------|
| `ui.edgeSwitch` | 是否开启无缝移动（默认开） |
| `ui.modMap` | 修饰键映射：`cmd-ctrl`（默认，推荐）/ `swap` / `off` |
| `ui.mouseSpeed` | 相对位移缩放（0.5 ~ 2，默认 1） |

实现要点（`src/input.js` + `src/peer.js`）：

- **键鼠模式两端同步**：选「共用本机键鼠」时，本机会把模式广播给对端，对端自动切到「只接收」；
  选「共用对端键鼠」时对端自动开始捕获转发。两端同时都想当主机时按设备名字典序决定谁让步，
  不会来回反复。**这一步以前缺失，会出现「模式选了但没有一台在转发，鼠标出不去」**。
- **多显示器桌面范围**：捕获端不再用「主屏尺寸」判断边缘，而是由主进程用 Electron 的 `screen`
  算出整个虚拟桌面的范围（副屏在主屏左边时 x 为负数也一样），避免鼠标在副屏上乱跳。
- **相对位移**：鼠标只发 `dx/dy`，对端自己累加成绝对坐标注入。两台分辨率、缩放不同，
  速度与手感仍然一致，不会出现「一跳半个屏幕」。
- **锚点回拉**：libuiohook 的 `mousemove` 只有绝对坐标，指针顶到屏幕边缘后位移会变成 0，远端指针就卡住了。
  所以转发期间把本机指针不断拉回**当前所在那块屏**的中心，保证始终能取到真实位移。
- **幻影指针**：host 侧自己维护「对端指针在哪」的坐标，一旦越过对端屏幕的另一侧，
  就发 DDC 把画面切回来，并把本机指针放到对应的边上 —— 这就是「无缝」的来源。
- **不抢焦点**：目标机在所有屏上都没配接口（或 DDC 明确失败）时，键鼠焦点会**留在本机**，
  不会出现「本机指针被拉回中心、对端又没画面」的卡死感，状态栏会直接说明原因。
- **屏幕尺寸交换**：连上后双方互发 `meta`（平台 + 屏幕尺寸），跨分辨率时按比例落位。
- **按键复位**：每次切换都广播 `input-reset`，两端释放所有按住的修饰键，避免「一直按着 ⌘」。

> 已知限制：libuiohook 无法拦截本机输入（它只能监听，不能吞掉事件）。
> 所以共用期间按键除了发给对端，本机也会收到一份。建议把本机当前应用切到一个无输入焦点的地方。

### ⌘ Command 与 Ctrl 的跨平台兼容

`src/keymap.js` 负责把捕获到的按键翻译成「目标系统上语义相同」的按键：

| 模式 | Mac → Windows | Windows → Mac |
|------|---------------|---------------|
| **⌘ ⇄ Ctrl（默认）** | ⌘ 和 ⌃ 都发成 `Ctrl` | `Ctrl` 和 `Win` 都发成 ⌘ |
| 严格互换 | ⌘ → `Ctrl`，⌃ → `Win` | `Ctrl` → ⌘，`Win` → ⌃ |
| 不映射 | 原样转发 | 原样转发 |

默认档位下 `⌘C → Ctrl+C`、`Ctrl+C → ⌘C` 都成立，这也是绝大多数人期望的行为。
两端是同一种系统时自动不做任何映射。

另外两层容错：
- **以 VC 虚拟键码为准**：`uiohook-napi` 只给 VC 键码（跨平台一致），VK/ASCII 仅作兜底；
  小键盘、方向键这类码位重叠的键单独成表，避免误判成字母。
- **按键诊断开关**（`ui.keyDebug`）：打开后在状态栏打印 `keycode / keychar → token → 映射后`，
  个别键不对时把它打开按一下，就能看到到底是哪一层出的问题。

## 传输与剪贴板

**剪贴板**
- 打开「开启剪贴板同步」后，在任意一台复制文字 / 截图 / 图片，另一台直接粘贴。
- 关闭同步不影响发文件与发文字。

**发文件**
- 入口：「传输与剪贴板」标签页，把文件/文件夹拖进虚线框，或点「选择文件」（支持多选与整个文件夹）。
- 发送前先在「发送到」里选中接收对象（有多台对端时可点选，默认选中第一台）。
- 勾选「超过 1GB，发送前询问」时，大于 1GB 的内容会先弹确认框。

**收文件**
- 默认**每次都会先问**：「接收 / 取消」。点「取消」会立即通知发送方（对端记录显示「对方已拒绝」）。
- 勾选「免确认自动接收文件」后不再询问（默认关闭）。
- 文件落在「接收目录」，同名自动加 `(1)`，可在记录里「在文件夹中显示」。

**传输记录**
- 每条记录右侧的 `×` 删除单条；「清空已结束」一次性清掉已完成 / 失败 / 取消的记录（**正在传的会先取消**）。
- **文本记录**：点整行或「查看」打开全文弹窗（可选中复制），「拷贝」直接进剪贴板。
- **文件记录**：点整行或「在文件夹中显示」，会打开所在目录并**选中该文件**（发出的记录指向本地源文件）。

**发文字**
- 在输入框写内容 → 点「发送文字」（或 Ctrl/⌘ + Enter）。
- 对方会**直接弹出文本内容**，并带一个「拷贝到剪贴板」按钮，一键粘到当前应用。

**协议**
- 复用同一条 WebSocket 连接：`file-offer → file-accept → file-chunk(256KB base64) → file-done`，
  拒绝走 `file-reject`，取消走 `file-cancel`；文字走 `text-send`。
- 接收端**串行写盘**（避免 `file-done` 早于最后一块落盘导致文件写串），发送整个文件夹时会还原同名目录结构。
- 发送期间每个分块之间会让出事件循环，界面刷新节流到 ~10fps，避免影响键鼠转发。

### v0.8.4

- **修：Windows 上明明接着 2 块屏，却只有 A 被判定为「在用」，B 一直是灰的。**
  根因是 v0.8.2 遗留的假接口配置：B 屏实际接在 DVI（`0x3`），配置里却存着 HDMI1，
  归属判定按「当前输入源 == 某台设备的口」去比对，永远对不上 → 判不出归属 → 不亮。
- **新增一条决定性证据：本机的 DDC 能枚举到这块屏，就说明这块屏此刻正在显示本机。**
  显示器切到别的机器后，系统会认为这块屏已断开，压根枚举不到（Windows 的 dxva2 走
  `EnumDisplayMonitors`，macOS 的 m1ddc 也只列活动显示器）。既然它正在显示本机，
  **它当前的输入源就是本机在这块屏上的口** —— 配置里存了别的值，就是存错了，自动纠正。
  在真机上实测：把两块屏的接口故意都写成 HDMI1，重新检测后 B 自动纠正为 DVI、两块屏都判定为本机在用。
- 这条规则不会让两台机器互相打架：屏幕显示谁，就只有谁枚举得到它、也只有那一方能读到这个口，
  同一个口不可能被两台同时读成「自己的」。
- 枚举得到但**读不到**当前输入源（不少显示器不支持读 VCP 0x60）时，不再整块屏发灰，
  直接判定为本机在用；接口配置则保持原样不动，免得把对的改错。
- 对端同步过来的接口如果正好是「本机正在用的口」，直接拒收 —— 一块屏的一个口只接一根线。
- 界面：一台电脑全部屏都在显示它时，不再重复显示「全部显示中 + 全部显示中」。

### v0.8.2

- **修：切一台电脑要等一整轮「谁在显示 → 转给谁」，多屏经常只切一块、甚至切反**
  以前 DDC 计划按「这块屏当前是哪台机器在显示」分组，够不着的屏把 `index + 值` 转给对端执行。
  但两端的 DDC 枚举顺序、显示器名字经常对不上（Windows 的 DDC 描述常常全是 `Generic PnP Monitor`），
  于是索引一错位就会「只切了一块」「切反」，或者对端报一个假错误码。
  现在改成：**DDC 是走视频线的，本机接了哪块屏，本机就直接写哪块**，跟这块屏当前画面在哪台机器上无关。
  - 每台机器只切「自己枚举得到」的屏，用**自己的**接口配置，不做跨机器的 index / 名字换算；
  - 有屏本机确实够不着（没接这根线 / 本机 DDC 不可用）时，才发一句 `switch-target` 给对端，
    对端也只切它自己连着的屏 —— 不再传值、不再换算；
  - 单块显示器切换同理，直接本机写，不再转给「当前在显示它的那台」。
- **修：排列图和系统设置里的排列对不上**（本次最直观的改动）
  - 读 Electron `screen.getAllDisplays()` 的真实坐标，按 (x, y) 排序、按相对大小等比绘制；
  - **笔记本内建屏**也画进图里（灰显、标「内建」，不参与切换、不占快捷键），
    以前它没有 DDC，会被当成空位顶掉某块外接屏的位置，导致 A/B 编号错位；
  - 型号名重复（Windows 上很常见）时不再用名字配对，直接按坐标从左到右对应。
- **改：电脑与显示器分开着色**，不再整行选中
  每台设备一个颜色；只有「正在用」的电脑本身和它点亮的屏上色，其余保持灰色。
  例：电脑 1 显示显示器 A、电脑 2 显示显示器 B → 电脑 1 和 A 同色，电脑 2 和 B 另一种颜色，都没点亮的屏不着色。
- **切换优先于共用键鼠**
  - 手动切换（点电脑 / 点显示器 / 快捷键）后 1.5 秒内不响应「鼠标推到边缘自动切换」，
    免得刚切过去、鼠标还压在屏幕边上，一动又被弹回来；鼠标推边缘触发的切换不加锁，无缝移动不受影响；
  - 共享键鼠与切换不再互相抢：切换时先松掉所有按住的修饰键、清掉幻影指针，再按新的焦点继续。
- **接口配置两端共享 + 自动学习**
  - 在任一台电脑上配好某块屏的接口，会同步给对端（按显示器名字合并，本机手改优先）；
  - 一块屏此刻显示的是哪台机器，它的当前输入源就一定是那台机器接的口 —— 发现「这台机器还没给这块屏配接口」
    就自动记下来。绝大多数场景不用手配，点一下就能切；
  - 真没配到时，状态栏会点名是哪块屏没有配：「DELL U2414H」还没设 X 的接口。

### v0.8.1

- **修：键鼠捕获根本起不来（`Cannot find module ...\iohook\builds\electron-v125-win32-x64\...iohook.node`）**
  Windows 安装版里 `iohook` 一直是坏的：它的二进制是**按 Electron 版本预编译**下载的，
  官方只出到很老的 Electron ABI；包里又没有 `binding.gyp`，`electron-rebuild` 连认都认不出来
  （CI 日志里只有 `Building modules: robotjs`）。所以打包后必然缺 `.node`，键鼠捕获永远失败，
  「共用键鼠」整个功能不可用。现在捕获层**换成 `uiohook-napi`**：
  - **N-API + 包内自带预编译**（win32-x64 / darwin-arm64 / darwin-x64 都在 tarball 里），
    不依赖 ABI、不需要编译、Electron 升级也不用重编；
  - 已实测：预编译 `.node` 在本机能加载、`start()/stop()` 正常；
  - 打包时把 `node_modules/uiohook-napi/prebuilds/**` 和 robotjs 的 `.node` 一并放进
    `asarUnpack`，避免「asar 里的原生模块加载不到」；
  - 捕获器启停状态拆成 `bound`（监听器已挂）/ `running`（hook 已启动），
    哪个环节失败都不会再变成「再也起不来」的僵尸状态；macOS 没授权时会直接告诉你去哪里勾。
- **修：「全部切到这台」只切一块屏 / 单块切换报「错误码 203」**
  - 根因一：**串行写 DDC 必然漏屏**。第一块屏切走之后 Windows 立刻重排显示拓扑，
    剩下几块屏的 handle 当场失效，第二次 `SetVCPFeature` 就失败。
    现在 C# 里**多线程同时下发**（同一瞬间发出所有写指令），再**重新枚举校验**：
    切走的屏会从枚举里消失（= 成功），还在列表里的用**新 handle 重试**（最多 4 轮）。
  - 根因二：「全部切到这台」原来按 `index` 下发，索引一旦漂移就切错/漏切。
    现在所有屏同一接口时直接下发 `*=值`（**枚举到几块就切几块**），完全不依赖 index；
    外层再补一次重试，第二次 `*` 正好只命中还没切走的那几块。
  - 根因三：「错误码 203」是假的。旧脚本要先 `Write-Output` 再 `GetLastWin32Error()`，
    控制台写入会把 last-error 冲掉，于是报出来一个无意义的 203。
    现在错误码在 C# 里**紧接着调用取**，并翻译成人话（31=显示器没开 DDC/CI、5=系统拒绝访问、
    6=句柄失效、GONE=这块屏已经不在本机）。
  - macOS 侧同样加了「每次枚举后按名字重新定位 + 失败重试」，跳过自带屏（它没有 DDC，
    跟着切只会每次都报部分失败）。

  - WebSocket 握手头里填错了身份 —— 发起方把自己「对端的名字」写进了 `x-peer-name`，

  - 「设备与显示器」右侧会直接提示「没有其它设备在线」，不再让人以为软件没在跑。
- **修：显示器排列顺序不对** —— 现在用 Electron `screen` 读到的显示器真实坐标
  （左 / 右 / 上 / 下）给 DDC 枚举出来的显示器定位并排序，**显示器 A 就是系统里最左边那块**；
  Windows 上把 DIP 换算成物理像素，和键鼠捕获坐标系一致。
- **修：「全部切到这台」只切了一块屏**
  - Windows 的内嵌 C# 现在**只在进程开始时枚举一次显示器**，之后一直用这批 handle 下发。
    之前每写一次都重新枚举，第一块屏切走之后系统立刻把它从枚举里摘掉，后面的 index 全部错位，
    第二块要么被跳过要么切错。
  - 所有屏用同一个接口时，计划压成一个值下发，执行端「所有屏一起切」，不再依赖两台机器的 index 一致。
  - 中转给对端执行的屏会带上**显示器名字**，对端按名字换成本机的 index（macOS 切走一台后序号也会前移，
    每一步都按名字重新定位）。
- **修：选了「共用某台电脑的键鼠」鼠标却出不去**
  - 键鼠模式现在**两端同步**：选中谁当主机，对端自动切到「只接收」；反向也一样。
    （以前只改本机配置，两台都按自己的模式跑，结果没有一台在转发。）
  - 捕获端的边缘判断改用**整块桌面范围**，副屏不会再被误判成边缘。
  - 目标机没配接口 / DDC 失败时**不再抢走键鼠焦点**，本机指针不会卡在屏幕中间。
  - 启动时按键鼠模式校正 `shareInput / isHost`，选「各用各的」不会被旧配置偷偷开启捕获。
- **传输记录可管理**：单条删除、清空已结束；文本记录点开看全文并一键拷贝；文件记录点一下
  在文件夹中选中该文件（发出的文件指向本地源文件）。
